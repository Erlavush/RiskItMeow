# Project

**Risk It Meow**

Risk It Meow is currently a manual-feature Godot prototype. The active scene includes one player, an `8x8` room shell with four walls and a roof, a room-view orbit camera, a runtime furniture placement system, a camera-driven wall cutaway system, and a developer environment tuning panel. Future work is still added manually, one feature request at a time.

**Core Value:** Keep the project easy to extend by preserving a clean baseline and only adding explicitly requested features.

## Useful Notes

- The live room is `8x8`, with `0.25` floor thickness, `0.25` wall thickness, four walls, and a roof.
- The active floor uses a dark-brown linen texture that is downscaled to `32x32`, repeated once per floor block, and randomly rotated per tile.
- Placement uses a browser-style left panel with `Inventory` and `Shop` tabs, category tabs, Build/Edit modes, save/load controls, and floor-finish switching.
- The active runtime catalog now uses one data-driven imported-item pipeline for the curated live items; the old large FBX household pack has been removed from the repo.
- Shop and inventory cards now use generated PNG thumbnails from `assets/ui/item_previews` for the live curated catalog instead of live runtime 3D preview scenes.
- Thumbnails are generated by [generate_item_previews.gd](/Z:/RiskItMeow/risk-it-meow/scripts/tools/generate_item_previews.gd).
- Placement supports floor items, wall-mounted windows, wall cutouts, gizmo drag, preview validity, double-click edit selection, move/duplicate/delete, and autosave.
- Room layouts persist locally in `user://room_layout.json`, including placed items, transforms, owned inventory totals, and floor finish.
- The editor 3D preview mirrors the locally saved room layout by reading `user://room_layout.json` through tool-mode preview logic.
- The developer panel can tune lighting, fog, glow, and post-adjustment live, persists locally in `user://`, and reapplies that saved preset in the editor preview.
- The developer panel includes persistent `Morning`, `Noon`, `Sunset`, and `Afternoon Cozy` sun presets.
- The room uses a first-pass Sims-style cutaway controller: camera-facing walls and the roof switch to render-only cutaway mode while preserving collisions and shadows.
- Windows use a lightweight sunlight workaround: sun-facing windows inject warm interior portal light plus a soft room bounce light.
- The `temporary/` pizzeria source tree is intentionally hidden from Godot scanning with `.gdignore` to avoid duplicate UID warnings while preserving old dependency paths.
- Curated live items and any future re-enabled props should go through the same data-driven imported-item catalog path so debug tuning and placement stay on one system.
- Local Godot executable paths are documented in [LOCAL_TOOLING.md](/Z:/RiskItMeow/risk-it-meow/LOCAL_TOOLING.md). The executables live in the project root: `.\Godot_v4.6.1-stable_win64.exe` and `.\Godot_v4.6.1-stable_win64_console.exe`. Use these for headless script runs, editor launches, and automation.

## Coding Discipline

These rules apply to ALL code changes — whether done directly or applied from ChatGPT output.

- **Simplicity first.** Minimum code that solves the request. No speculative features, no "flexibility" that wasn't asked for.
- **Surgical changes.** Only touch what the request requires. Don't "improve" adjacent code, comments, or formatting. Match existing style.
- **Clean up your own mess only.** Remove imports/variables/functions that YOUR changes made unused. Don't remove pre-existing dead code unless asked.
- **State assumptions.** If multiple approaches exist, present them — don't pick silently. If something is unclear, ask before coding.
- **Verify before claiming done.** Every change should have a clear way to verify it works (run the game, check output, etc.).

## GPT Workflow — `gpt:` Trigger

When the user's message starts with `gpt:` followed by a request, this is a **ChatGPT-assisted development pipeline**. The local AI model acts as the "hands" (runs scripts, applies edits) while ChatGPT Web acts as the "brain" (analyzes the codebase, designs the solution, writes the code).

### Step-by-Step Process

**Step 1 — Snapshot the codebase**
Run the snapshot script to generate a fresh `codebase_snapshot.txt`:
```
.\Godot_v4.6.1-stable_win64.exe --path . -s scripts/tools/snapshot_codebase.gd --headless
```

**Step 2 — Read the system prompt**
Read the file `scripts/tools/chatgpt_system_prompt.txt`.

**Step 3 — Send to ChatGPT (ONE call only)**
Use the Proxima MCP tool `ask_chatgpt` to send:
- The `codebase_snapshot.txt` file as an attachment (use the `files` parameter)
- The message should combine: the system prompt text + the user's actual request

Example message format:
```
<contents of chatgpt_system_prompt.txt>

---

USER REQUEST: <whatever the user typed after "gpt:">
```

The `ask_chatgpt` call blocks internally (inside Proxima) until ChatGPT finishes responding. This costs ZERO tokens while waiting. Use the returned response directly.

**CRITICAL: Do NOT call `get_typing_status`. Do NOT send follow-up messages. Do NOT make a second `ask_chatgpt` call. ONE call, ONE response.**

**Step 4 — Present for review**
Show the user:
- ChatGPT's **ANALYSIS** and **PLAN** sections
- A summary of which files will be created/modified/deleted
- Do NOT apply any changes yet

**Step 5 — Wait for approval**
Wait for the user to say "go ahead", "do it", "apply", or similar confirmation.

**Step 6 — Apply changes**
Parse ChatGPT's response for `%%% FILE: path [ACTION] %%%` blocks:
- `[NEW]` → Create the file with the provided content using `write_to_file`
- `[MODIFY]` → Overwrite the file with the provided content using `write_to_file` with `Overwrite: true`
- `[DELETE]` → Delete the file
- Convert `res://` paths to absolute paths (e.g., `res://scripts/foo.gd` → `z:\RiskItMeow\risk-it-meow\scripts\foo.gd`)

If there are SCENE CHANGES instructions, use the Godot MCP tools (`add_node`, etc.) or apply them manually.

**Step 7 — Report**
Tell the user what was applied and suggest how to test it.

### Key Files

| File | Purpose |
|------|---------|
| `scripts/tools/snapshot_codebase.gd` | Generates codebase snapshot (extends SceneTree, CLI-runnable) |
| `scripts/tools/chatgpt_system_prompt.txt` | System prompt that forces ChatGPT to use structured output format |
| `codebase_snapshot.txt` | Generated output (regenerated each run, do not commit) |
